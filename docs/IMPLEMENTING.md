# Recipe sections

Add independent ingredient and instruction headings as nullable `section` columns
on the existing ordered rows. A section is a consecutive run, not an entity.
Existing recipes remain unchanged, with NULL sections, through additive migration
0006 generated by Drizzle.

Domain validation trims headings, converts blank input to NULL, limits names to
80 characters, rejects unheaded items after a heading and case-insensitive names
repeated in separate runs. Database checks reject blank or untrimmed labels.
Inputs remain optional for compatibility. Empty headings cannot be saved.

Carry sections through recipe writes, reads, imports and MCP. Preserve imported
HowToSection names and ingredient headings, including pasted sauce headings.
Display headings in recipe detail and cooking checklists without restarting step
numbers. Add independent section controls to the form and import review, with
rename, move and removal that retains items. Item up/down controls cross headings.
Seed one sectioned recipe. Scaling and grocery aggregation ignore headings and
grocery snapshots do not acquire sections; soft-delete restoration retains them.

Test domain rules, API create/update/read and restore, migration compatibility,
imports, web forms/detail, MCP and a Playwright section-editing journey. Run
typecheck, tests, build and E2E where supported; report environmental blockers.

Finish by recording the rejected separate section table in a new ADR and adding
linked component recipes to IDEAS (grocery expansion versus kept-on-hand, yield,
cooking navigation, trashed links, cycles and suggestions). Linked recipes are
not part of this implementation. Preserve other durable reasoning in comments,
then delete this brief in the same final documentation commit. No pull request.
